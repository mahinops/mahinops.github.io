Prefix Sum

Do one pass up front so every later question takes a single subtraction.

The idea

Think of a bank statement showing a running balance after every transaction. How much did you spend between transaction 3 and transaction 6? You do not re-add the spending: you take the balance after #6 and subtract the balance before #3.

A prefix sum array p is that running balance: p[i] is the sum of the first i numbers. The sum of nums[l..r] is then p[r+1] − p[l]. We add one extra slot p[0] = 0 (the sum of nothing) so the formula works even when l is 0.

Watch it work

Try it

  • Query l = 0, r = 0. Which two prefix cells are used, and why is p[0] = 0 needed?
  • Query the whole list (l = 0, r = last index). Which single prefix cell holds the total?
  • Add negative numbers (like 5, -2, 7). The method still works. Why?
  • Count the work: building is one pass, but a query is always just one subtraction no matter how wide the range.

Common mistakes

  • Forgetting the extra leading 0: without p[0] = 0 the range starting at index 0 needs a special case.
  • Off-by-one: for an inclusive range [l, r] the formula is p[r+1] - p[l], not p[r] - p[l].
  • Using it when the data changes: if values are updated often, the stored prefixes go stale. (That calls for a Fenwick tree.)

How fast is it?

Build: O(n) time once. Each query: O(1). Space: O(n) for the prefix array. Without it, every query would re-add up to n numbers (O(n) each).
