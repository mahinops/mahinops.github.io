Bit Manipulation

Every number is a row of on/off switches. Bit tricks flip those switches directly.

The idea (a row of light switches)

Inside the computer a number is stored in binary: a row of switches, each either 0 (off) or 1 (on). Each switch has a place value: from the right they are 1, 2, 4, 8, 16, 32, 64, 128. Add up the values of the switches that are on. For example 00001100 is 8 + 4 = 12. This page uses 8 switches (Go’s uint8, numbers 0 to 255).

  • AND (&): a column is 1 only if both numbers have 1 there. Great for checking or keeping bits.
  • OR (|): 1 if either has 1. Great for turning bits on.
  • XOR (^): 1 if the bits are different. Doing it twice with the same value undoes it, so equal numbers cancel to 0.
  • Shift (<< / >>): slide all switches left or right. Left by 1 doubles the number; right by 1 halves it.

Watch it work

Try it

  • AND, OR and XOR the same pair (12 and 10). Compare the three result rows column by column.
  • Shift 1 left by 7, then try 3 left by 7. What happens to the bit that falls off the left edge?
  • n & (n-1) on 8, 12, 255. Why does a power of two (like 8) become 0?
  • Count the 1 bits of 255 and of 128. How many loop steps does each need?
  • Single number: reorder the list. Does the answer change? Why not?

Common mistakes

  • Confusing & with &&. & works on bits of numbers; && works on true/false values.
  • Operator precedence. In Go, & binds tighter than ==, so a & b == 0 means (a & b) == 0. In C and some other languages it is the other way round, so add parentheses when in doubt.
  • Overflow when shifting. Bits shifted past the type’s width are lost. A uint8 cannot hold 1 << 8.
  • Signed shifts. Right-shifting a negative int keeps the sign bit; this page uses unsigned numbers to keep things simple.
Complexity, in plain English: AND, OR, XOR and shifts are single machine instructions (O(1)). Counting bits with n & (n-1) loops once per 1 bit, not once per bit position. The single-number trick scans the list once and needs no extra memory.
