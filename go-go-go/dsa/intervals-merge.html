Merge Intervals

Combine time ranges that overlap into the fewest ranges possible.

The idea (calendar meetings)

You have meetings at 1–3, 2–6 and 8–10. The first two overlap, so your calendar really shows one busy block from 1 to 6, plus 8–10. Merging intervals does that for any list.

The trick is to sort by start time first. Then overlapping ranges become neighbors, and one left-to-right sweep is enough:

  • Keep a list merged. Start it with the first interval.
  • For each next interval, compare its start with the end of the last merged interval.
  • If start ≤ that end, they overlap: stretch the last interval’s end to the larger of the two ends.
  • Otherwise there is a gap: start a new merged interval.

Try it

  • Type the intervals in a jumbled order (the default is). Does the sort make the sweep work?
  • Try 1-10, 2-3, 4-5. When the new interval is completely inside the last one, why must we use max for the end?
  • Try 1-3, 3-5. They only touch at 3. Does this code merge them?
  • Try intervals with gaps everywhere, like 1-2, 4-5, 7-8.

Common mistakes

  • Forgetting to sort. Overlapping intervals might not be neighbors, and the sweep silently gives a wrong answer.
  • Setting the end to cur[1] instead of max(last[1], cur[1]). An interval nested inside another would shrink the result.
  • Off-by-one on touching ranges. Whether [1,3] and [3,5] merge depends on <= versus <. Read the problem statement.
  • Empty input. intervals[0] panics on an empty slice, so check the length first.
Complexity, in plain English: sorting costs the most, about n log n steps (O(n log n)). The sweep afterwards is a single pass (O(n)).
