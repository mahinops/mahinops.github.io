Binary Search

Find a value in a sorted list by repeatedly throwing away half of it.

The idea (like guessing a number)

I think of a number from 1 to 100. You guess 50. I say “higher”. Now you know it is in 51–100, so half the numbers are gone with one guess. Guess 75, “lower”… In about 7 guesses you always win. That is binary search: look at the middle, then discard the half that cannot contain the answer.

It only works if the list is sorted. Doubling the list size adds just one more step: 1,000,000 items need about 20 steps.

Watch it work

Try it

  • Search for 91 (the last item) and for 2 (the first). How many steps each?
  • Search for 40, which is not in the list. What do lo and hi look like at the end?
  • Add 10 more numbers (keep them sorted). How many extra steps does it need?
  • Type an unsorted list. Why does it fail?

Common mistakes

  • Off-by-one: after checking mid, move to mid+1 or mid-1, not mid, or you can loop forever.
  • Overflow: write mid := lo + (hi-lo)/2, not (lo+hi)/2, which can overflow with huge indexes.
  • Unsorted input: the answer is silently wrong.
