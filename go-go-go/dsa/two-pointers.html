Two Pointers

Use two index markers instead of two nested loops.

The idea

Imagine two people walking toward each other along a sorted row of numbered stones, one from each end. You want two stones that add up to a target. If the sum is too small, the left person steps right to a bigger stone. If it is too big, the right person steps left to a smaller one. Each step rules out a stone for good, so one pass is enough.

The same trick reverses a list in place: swap the two ends, move both markers inward, repeat until they meet.

Watch it work

Try it

  • Pair mode, target 14: watch which pointer moves each time and why.
  • Change the target to 100. When do the pointers stop, and what is returned?
  • Put the numbers out of order. The page refuses. Why would two pointers give wrong answers on unsorted data?
  • Switch to Reverse with an odd count (like 5 numbers). What happens to the middle one?

Common mistakes

  • Unsorted input: “too small, move left” only makes sense when the list is sorted.
  • Using l <= r instead of l < r in pair problems lets an element pair with itself.
  • Moving the wrong pointer: if the sum is too small, only the left pointer can help (it points at the smallest candidate).

How fast is it?

Time: O(n) – the pointers only ever move inward, so each item is looked at at most once. A nested-loop version needs O(n²). Space: O(1) – just two integers.
