Context and Cancellation

A context.Context is a stop button and a deadline that you pass down to everything doing work.

The idea

You order food and tell the kitchen “if it is not ready in 20 minutes, cancel it”. Every cook working on your order can look at the same clock: when it rings, they all stop and clean up instead of finishing something nobody wants.

A context is that shared clock/stop button. context.WithCancel gives you a button; WithTimeout presses it automatically after a time. Contexts form a tree: cancelling a parent cancels every child below it, never the other way round. Work listens with <-ctx.Done().

Watch it work

Try it

  • Set work to 50 and timeout to 100, then work to 200. What does ctx.Err() say?
  • In “Cancelling a parent” cancel grand, then childA, then parent. Which contexts stay alive each time?

Common mistakes

  • Not calling the cancel function (defer cancel()): the context and its timer leak until the parent ends.
  • Storing a context in a struct. Pass it as the first parameter: func Do(ctx context.Context, ...).
  • Ignoring ctx.Done() in long loops, so work keeps running after the caller gave up.
  • Using WithValue for ordinary parameters. It is for request-scoped data like trace IDs.
