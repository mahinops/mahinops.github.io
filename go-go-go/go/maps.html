Maps

A map is a phone book: look something up by its key, get its value.

The idea

A phone book maps a name to a number. You never ask for “the third entry”; you ask for “Ada”. A Go map[string]int is the same: keys of one type, values of another, and lookups are fast no matter how big the book gets.

Two things surprise newcomers: asking for a missing key gives the zero value (not an error), so you use v, ok := m[k] to tell “missing” from “present but zero”; and the order of a loop over a map is deliberately random.

Watch it work

Try it

  • In “comma-ok lookup” look up cy (stored value 0) and zed (missing). Both give v = 0. How do you tell them apart?
  • In “Iteration order” press Run several times. Does the order stay the same?
  • In “nil map” find which line is allowed (a read) and which one panics (a write).

Common mistakes

  • Writing to a nil map: panic: assignment to entry in nil map. Create it with make(map[K]V) or a literal first.
  • Relying on iteration order. Collect the keys, sort them, then loop over the sorted keys.
  • Using m[k] to test existence. Use _, ok := m[k].
  • Using a slice or a map as a key: keys must be comparable (strings, numbers, structs of those, ...).
