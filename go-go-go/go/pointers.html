Pointers

A pointer is a box that holds the address of another box. Draw it as an arrow.

The idea

Imagine a friend’s house. A value is the house itself. A pointer is a note with the house’s street address written on it. If you hand someone a photocopy of the house (pass by value) they can paint it and your house stays the same. If you hand them the address note (a pointer) they can walk there and paint your real house.

Two symbols do all the work: &x means “the address of x” (make the arrow) and *p means “go where p points” (follow the arrow, to read or write).

Watch it work

Try it

  • In “Address-of and dereference” change the new value written through *p and see x change without being named.
  • In “Pass by value vs pointer” step slowly: which function changes the caller’s x, and why?
  • In “nil pointer” find the exact step where the program crashes.
  • In “Two pointers, one target” write through one pointer and read through the other.

Common mistakes

  • Dereferencing a nil pointer panics: invalid memory address or nil pointer dereference. Check p != nil first.
  • Expecting a function to change your variable when you passed it by value. Pass &x and take a *int parameter instead.
  • Mixing up p (the address) and *p (the value it points to). Printing p shows an address, not your data.
  • Returning a pointer to a local variable is fine in Go (it moves to the heap), unlike C.
