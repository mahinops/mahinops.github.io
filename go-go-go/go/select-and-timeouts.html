Select and Timeouts

select waits on several channels at once and runs the one that is ready first.

The idea

You are waiting for a parcel, a phone call, or an alarm clock, whichever comes first. You do not stare at one door; you sit and wait for any of them, then deal with that one and forget the rest.

select does exactly that with channels. time.After(d) is a channel that delivers a value after d, so using it as one case gives you a timeout. A default case means “do not wait at all”.

Watch it work

Try it

  • Set ch1 to 50, ch2 to 20 and the timeout to 100. Who wins? Then raise ch2 to 150.
  • Set the timeout smaller than both channels to see the timeout case win.
  • Make ch1 and ch2 equal. When several cases are ready at once, real Go picks one at random.

Common mistakes

  • Using time.After in a hot loop creates a timer each iteration; for loops prefer time.NewTimer or a context.
  • Adding default when you meant to wait: the select then never blocks and a loop around it spins at 100% CPU.
  • Assuming cases are checked top to bottom. When several are ready, one is chosen at random.
  • Reading from a nil channel in a case blocks forever (useful on purpose, a bug by accident).
