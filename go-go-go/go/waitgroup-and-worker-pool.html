WaitGroup and Worker Pool

A worker pool runs a fixed number of workers over a queue of jobs. A WaitGroup lets main wait until all jobs are done.

The idea

A supermarket has 3 checkout lanes (workers) and a line of customers (jobs). When a lane frees up, it takes the next customer. You do not open 1000 lanes for 1000 customers; you reuse a few.

The manager needs to know when everyone has been served. A sync.WaitGroup is a counter: Add(1) for each job, Done() when one finishes, and Wait() blocks until the counter reaches zero.

Watch it work

Try it

  • Use 1 worker, then 2, then 4 with the same jobs. How does the total time change?
  • Make one job very long (e.g. 9) and the rest short. Does it block the other workers?
  • Watch the WaitGroup counter: when exactly does Wait() return?

Common mistakes

  • Calling wg.Add inside the goroutine: Wait might run before Add. Add before starting the goroutine.
  • Forgetting wg.Done() (use defer wg.Done()): Wait blocks forever.
  • Not closing the jobs channel: workers ranging over it never stop.
  • Passing a WaitGroup by value. It must be shared by pointer.
