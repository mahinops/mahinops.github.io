Interfaces

An interface value is a two-slot box: which type is inside and the value itself.

The idea

An interface is a job description: “anyone who can do Area()”. A rectangle can do it, a circle can do it, and neither has to announce that it “implements” the interface. If the methods are there, it fits.

Inside, an interface variable is a box with two slots: a type label (what is actually stored) and the value. When you call s.Area(), Go reads the type slot, finds that type’s Area, and runs it on the value. An interface is nil only when both slots are empty, which is the source of a famous gotcha.

Common mistakes

  • Returning a typed nil pointer as an interface (var p *MyErr; return p) makes a NON-nil interface. Return a literal nil instead.
  • Making interfaces too big. Small interfaces (one or two methods, like io.Reader) are easier to satisfy and to test.
  • Defining the interface next to the implementation. In Go it usually belongs with the code that uses it.
  • A bare x.(T) panics if x holds another type. Use v, ok := x.(T) when unsure.
