Goroutines and Channels

A goroutine is a task running alongside others. A channel is a pipe they use to pass values.

The idea

A goroutine is like an extra worker in a kitchen: go f() says “you, start doing f, I will carry on”. Workers should not reach into each other’s pockets; they hand things over a channel, like a slot in the kitchen wall.

An unbuffered channel has no shelf: the cook and the waiter must meet at the slot at the same moment, so whoever arrives first waits (blocks). A buffered channel has a shelf with room for N plates: the sender only waits when the shelf is full, the receiver only when it is empty. close(ch) tells the receivers “no more plates are coming”.

Note: real Go chooses the order in which goroutines run. These animations show one possible schedule.

Try it

  • In “Buffered channel” set capacity to 1, then 4. How does the producer’s waiting change?
  • In “Sender blocks” find the moment the sender finally continues. What triggered it?
  • Remove the close in your head: what would the range loop do at the end? (It would wait forever.)

Common mistakes

  • Receiving from a channel nobody sends to: fatal error: all goroutines are asleep - deadlock!
  • Sending on a closed channel panics. Only the sender should close, and only once.
  • Forgetting to close a channel that a range loop reads: the loop never ends.
  • Starting goroutines that can never finish (blocked forever) is a goroutine leak.
