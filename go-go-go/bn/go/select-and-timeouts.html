Select and Timeouts

select একসাথে কয়েকটা channel-এর জন্য অপেক্ষা করে এবং যেটা আগে ready হয় সেটা run করে।

মূল ধারণা

আপনি একটা parcel, একটা ফোন কল, বা একটা alarm clock-এর জন্য অপেক্ষা করছেন, যেটা আগে আসে। আপনি একটা দরজার দিকে তাকিয়ে বসে থাকেন না; বসে থাকেন যেকোনো একটার অপেক্ষায়, তারপর যেটা এল সেটা সামলান আর বাকিগুলো ভুলে যান।

select channel দিয়ে ঠিক এই কাজটাই করে। time.After(d) হলো এমন একটা channel যা d সময় পরে একটা value দেয়, তাই এটাকে একটা case হিসেবে ব্যবহার করলে আপনি একটা timeout পান। default case মানে “একদম অপেক্ষা করো না”।

Run করে দেখুন

নিজে চেষ্টা করুন

  • ch1 50, ch2 20 আর timeout 100 দিন। কে জেতে? তারপর ch2 150 করুন।
  • Timeout-কে দুটো channel-এর চেয়েই ছোট করুন, তাহলে timeout case-কে জিততে দেখবেন।
  • ch1 আর ch2 সমান করুন। একসাথে কয়েকটা case ready থাকলে আসল Go random-ভাবে একটা বেছে নেয়।

সাধারণ ভুল

  • Hot loop-এ time.After ব্যবহার করলে প্রতি iteration-এ একটা করে timer তৈরি হয়; loop-এর জন্য time.NewTimer বা context ব্যবহার করুন।
  • অপেক্ষা করতে চাইলে default যোগ করা: তখন select কখনো block হয় না, আর তার চারপাশের loop 100% CPU নিয়ে ঘুরতে থাকে।
  • ভাবা যে case গুলো ওপর থেকে নিচে check হয়। একসাথে কয়েকটা ready থাকলে random-ভাবে একটা বাছা হয়।
  • কোনো case-এ nil channel থেকে পড়লে সেটা চিরকাল block হয় (ইচ্ছে করে করলে কাজের, ভুলে হলে bug)।
