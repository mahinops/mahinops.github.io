Mutex and Data Race

counter++ একটা একক কাজ নয়। এটা read, add, write, আর দুটো goroutine এই ধাপগুলো এলোমেলোভাবে মিশিয়ে ফেলতে পারে।

মূল ধারণা

দুজন মানুষ একটা whiteboard share করছে, যেখানে লেখা 0। প্রত্যেকে করে “সংখ্যাটা পড়ো, মনে মনে 1 যোগ করো, উত্তরটা আবার লিখে দাও”। দুজনেই যদি কেউ লেখার আগেই 0 পড়ে ফেলে, তাহলে দুজনেই 1 লিখবে, আর একটা increment হারিয়ে যাবে। বোর্ডে হবে 1, 2 নয়।

এটাই data race: দুটো goroutine একই সময়ে একই variable ছুঁয়ে আছে এবং কমপক্ষে একজন লিখছে। Mutex (mutual exclusion lock) হলো একটা কলম যেটা একসময় একজনই ধরতে পারে: কলমটা নাও (Lock), পুরো read-add-write শেষ করো, তারপর ফেরত দাও (Unlock)। কলম খালি না হওয়া পর্যন্ত আর কেউ শুরু করতে পারে না।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “আপনার নিজের interleaving” উদাহরণে 1 1 1 2 2 2 (কোনো overlap নেই) দিন, তারপর 1 2 2 1 1 2। কোন order-এ update হারায়?
  • “Mutex দিয়ে ঠিক করা” উদাহরণে blocked ধাপগুলো দেখুন: G1 unlock না করা পর্যন্ত G2 কেন পড়তে পারে না?
  • একটা আসল program go run -race . দিয়ে run করুন, তাহলে Go নিজেই race-টা report করবে।

সাধারণ ভুল

  • ভাবা যে counter++ atomic। এটা নয়; sync.Mutex বা sync/atomic ব্যবহার করুন।
  • Unlock করতে ভুলে যাওয়া (Lock-এর ঠিক পরেই defer mu.Unlock() লিখুন), যার ফলে বাকি সব goroutine আটকে যায়।
  • Mutex আছে এমন struct copy করা। এর বদলে pointer pass করুন।
  • একটা program test pass করেও race নিয়ে থাকতে পারে। go test -race ./... run করুন; race detector WARNING: DATA RACE print করে।
