Context and Cancellation

context.Context হলো একটা stop button আর একটা deadline, যেটা আপনি কাজ করছে এমন সবকিছুর কাছে পাঠিয়ে দেন।

মূল ধারণা

আপনি খাবার অর্ডার করলেন আর রান্নাঘরকে বললেন “20 মিনিটের মধ্যে ready না হলে cancel করে দাও”। আপনার অর্ডারে কাজ করা প্রতিটা রাঁধুনি একই ঘড়ি দেখতে পারে: ঘড়ি বাজলে সবাই এমন কিছু শেষ করার বদলে, যা কেউ চায় না, থেমে যায় আর গুছিয়ে নেয়।

Context হলো সেই share করা ঘড়ি/stop button। context.WithCancel আপনাকে একটা button দেয়; WithTimeout কিছুক্ষণ পর সেটা নিজে থেকেই চেপে দেয়। Context গুলো একটা tree বানায়: parent cancel করলে তার নিচের সব child cancel হয়, উল্টোটা কখনো নয়। কাজ শোনে <-ctx.Done() দিয়ে।

Run করে দেখুন

নিজে চেষ্টা করুন

  • work 50 আর timeout 100 দিন, তারপর work 200 করুন। ctx.Err() কী বলছে?
  • “Cancelling a parent” উদাহরণে প্রথমে grand, তারপর childA, তারপর parent cancel করুন। প্রতিবার কোন কোন context বেঁচে থাকে?

সাধারণ ভুল

  • Cancel function call না করা (defer cancel()): parent শেষ না হওয়া পর্যন্ত context আর তার timer leak হয়।
  • Context-কে struct-এ রেখে দেওয়া। এটাকে প্রথম parameter হিসেবে pass করুন: func Do(ctx context.Context, ...)।
  • বড় loop-এ ctx.Done() উপেক্ষা করা, ফলে caller ছেড়ে দেওয়ার পরেও কাজ run হতে থাকে।
  • সাধারণ parameter-এর জন্য WithValue ব্যবহার করা। এটা শুধু request-scoped data-র জন্য, যেমন trace ID।
