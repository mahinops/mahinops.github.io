Maps

Map হলো একটা ফোন বই: key দিয়ে খুঁজলে তার value পাওয়া যায়।

মূল ধারণা

ফোন বই একটা নাম-কে একটা নম্বর-এর সাথে জুড়ে রাখে। আপনি কখনো “তৃতীয় entry-টা দাও” বলেন না; বলেন “Ada-র নম্বরটা দাও”। Go-র map[string]int ঠিক এরকম: key এক type-এর, value আরেক type-এর, আর বইটা যত বড়ই হোক, খোঁজা দ্রুতই থাকে।

নতুনদের দুটো জিনিস অবাক করে: missing key চাইলে zero value পাওয়া যায় (error হয় না), তাই “নেই” আর “আছে কিন্তু মান zero” আলাদা করতে v, ok := m[k] ব্যবহার করতে হয়; আর map-এর ওপর loop-এর order ইচ্ছে করেই random।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “comma-ok lookup” উদাহরণে cy (রাখা মান 0) আর zed (নেই) খুঁজুন। দুটোতেই v = 0 আসে। তাহলে দুটো আলাদা করবেন কীভাবে?
  • “Iteration order random হয়” উদাহরণে কয়েকবার Run চাপুন। order কি একই থাকে?
  • “nil map” উদাহরণে খুঁজে বের করুন কোন লাইনটা করা যায় (read) আর কোনটা panic করে (write)।

সাধারণ ভুল

  • nil map-এ লিখলে: panic: assignment to entry in nil map। আগে make(map[K]V) বা একটা literal দিয়ে map বানিয়ে নিন।
  • Iteration order-এর ওপর নির্ভর করা। key গুলো collect করুন, sort করুন, তারপর sorted key দিয়ে loop করুন।
  • Key আছে কিনা দেখতে m[k] ব্যবহার করা। এর বদলে _, ok := m[k] ব্যবহার করুন।
  • Slice বা map-কে key হিসেবে ব্যবহার করা: key অবশ্যই comparable হতে হবে (string, সংখ্যা, এগুলো দিয়ে বানানো struct, ...)।
