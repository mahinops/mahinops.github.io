Closures

Closure হলো এমন function, যে আশেপাশের variable গুলো মনে রাখে, বাইরের function শেষ হয়ে গেলেও।

মূল ধারণা

কল্পনা করুন কাউকে একটা সিল করা খামে ক্যালকুলেটর দিলেন, যার সাথে একটা ছোট notepad আটকানো। সে যতবার “+1” চাপে, ততবার ওই খামের নিজের notepad-টাই update হয়। আরেকজনকে দ্বিতীয় একটা খাম দিলে সে পায় দ্বিতীয়, আলাদা একটা notepad।

Go-তে একটা function literal তার চারপাশের (যে function সেটা বানিয়েছে তার) variable ব্যবহার করতে পারে। closure যতক্ষণ থাকে, ততক্ষণ ওই variable গুলোও বেঁচে থাকে। counter()-এর প্রতিটা call একটা নতুন n তৈরি করে, তাই প্রতিটা closure আলাদাভাবে গোনে।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “Counter” উদাহরণে তীর অনুসরণ করুন: a() কি কখনো b-র counter বদলায়?
  • “Loop variable” উদাহরণে দুটো Go version বদলে বদলে দেখুন, আর তীর ও print হওয়া সংখ্যা মিলিয়ে নিন।

সাধারণ ভুল

  • Go 1.22-এর আগে (go.mod 1.22-এর পুরনো হলে) for i := ... loop-এ বানানো সব closure একটাই i share করত, তাই সবাই শেষ মানটা print করত। আধুনিক Go প্রতিটা iteration-কে নিজস্ব i দেয়।
  • কোনো variable capture করে পরে সেটা বদলালে closure সবচেয়ে নতুন মানটাই দেখে, বানানোর সময়ের মান নয়।
  • Loop-এর ভেতরে শুরু করা goroutine যেগুলো loop variable capture করত, সেগুলোই ছিল পুরনো behaviour-এর সবচেয়ে পরিচিত শিকার; আপনার go.mod-এর version দেখে নিন।
