Defer, Panic and Recover

defer হলো একটা to-do list, যেটা function শেষ হওয়ার সময় run হয়, নতুন item আগে।

মূল ধারণা

আপনি বাড়ি থেকে বের হচ্ছেন। যেতে যেতে কয়েকটা কাজের কথা মনে পড়ল: “oven বন্ধ করো”, তারপর “জানালা আটকাও”, তারপর “দরজায় তালা দাও”। বের হওয়ার আগে এগুলো মেটাতে হবে উল্টো ক্রমে: আগে দরজা (সবার শেষে যোগ হয়েছে), তারপর জানালা, তারপর oven। এটাই defer: call-এর একটা last-in, first-out stack, যা আশপাশের function return করার সময় run হয়, এমনকি panic-এর কারণে return হলেও।

Panic হলো জরুরি অবস্থা: স্বাভাবিক execution থেমে যায় এবং Go stack unwind করতে করতে deferred call গুলো run করে। কোনো deferred function যদি recover() call করে, তাহলে জরুরি অবস্থা বাতিল হয়ে যায় এবং function স্বাভাবিকভাবে return করে। কেউ recover না করলে program crash করে।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “Panic থেকে recover করা” উদাহরণে b = 2 দিন, তারপর b = 0। শেষের output দুটো মিলিয়ে দেখুন।
  • “defer উল্টো ক্রমে run হয়” উদাহরণে মনে মনে আরেকটা defer যোগ করুন: সেটা কোথায় print হবে?
  • “recover ছাড়া panic” উদাহরণে খেয়াল করুন crash-এর বার্তার আগেও cleanup print হয়।

সাধারণ ভুল

  • recover() শুধু তখনই কাজ করে যখন সেটা সরাসরি কোনো deferred function-এর ভেতরে call করা হয়। অন্য জায়গায় এটা nil return করে।
  • Loop-এর ভেতরে defer করা: সব deferred call function শেষ হওয়া পর্যন্ত অপেক্ষা করে, iteration শেষ হওয়া পর্যন্ত নয় (এতে file অনেকক্ষণ open থেকে যেতে পারে)।
  • Deferred call-এর argument গুলো evaluate হয় যখন defer লাইনটা run হয়, call-টা execute হওয়ার সময় নয়।
  • সাধারণ error-এর জন্য panic ব্যবহার করা। এর বদলে একটা error return করুন; panic রাখুন bug আর অসম্ভব অবস্থার জন্য।
