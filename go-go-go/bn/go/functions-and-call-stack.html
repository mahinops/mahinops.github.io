Functions and the Call Stack

প্রতিটা function call নিজের একটা frame পায়: caller-এর frame-এর ওপর সাজানো একটা আলাদা scratch-pad।

মূল ধারণা

ডেস্কে একটার ওপর একটা সাজানো sticky note-এর কথা ভাবুন। আপনি একটা কাজ করছেন (main)। একটা ছোট কাজ আলাদাভাবে করাতে হবে, তাই input গুলো লিখে একদম ওপরে নতুন একটা note রাখলেন এবং শুধু সেই note নিয়েই কাজ করলেন। কাজ শেষ হলে উত্তরটা পড়ে নিয়ে note-টা ফেলে দেন, আর নিচের note-এর কাজে ফিরে যান।

Argument গুলো নতুন note-এ copy হয়, তাই callee নিজের note-এ যা খুশি লিখলেও আপনারটায় হাত পড়ে না। যে function নিজেকেই call করে (recursion), সে এমন একটা case পর্যন্ত note জমাতে থাকে যার উত্তর সাথে সাথে দেওয়া যায়; তারপর উত্তরগুলো stack বেয়ে নিচে ফিরে আসে।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “Recursion: factorial” উদাহরণে n = 1, তারপর 4, তারপর 8 দিন। সবচেয়ে গভীর মুহূর্তে কতগুলো frame থাকে?
  • “Multiple return values” উদাহরণে b = 1 দিন, তারপর 7। q আর r লক্ষ করুন।
  • খেয়াল করুন callee কখনো caller-এর variable বদলায় না, কারণ তার input গুলো ছিল copy।

সাধারণ ভুল

  • Recursion-এ base case ভুলে যাওয়া। stack বাড়তেই থাকে, শেষে Go জানায় stack overflow: fatal error: stack overflow।
  • Copy pass করে আশা করা যে function আপনার variable বদলে দেবে। বদলাতে চাইলে pointer pass করুন।
  • Error result উপেক্ষা করা: v, _ := f() লিখলে কাজটা fail হয়েছে কিনা সেই তথ্য ফেলে দেওয়া হয়।
  • ব্যবহার না করা function parameter থাকলে সমস্যা নেই, কিন্তু ব্যবহার না করা local variable থাকলে compile error হয়।
