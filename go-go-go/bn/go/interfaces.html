Interfaces

Interface value হলো দুই slot-ওয়ালা একটা box: ভেতরে কোন type আছে আর value-টা নিজে।

মূল ধারণা

Interface হলো একটা job description: “যে কেউ Area() করতে পারে”। rectangle পারে, circle-ও পারে, আর কাউকেই আলাদা করে বলতে হয় না যে সে interface-টা “implement” করছে। method গুলো থাকলেই সে মানিয়ে যায়।

ভেতরে interface variable হলো দুটো slot-ওয়ালা একটা box: একটা type-এর লেবেল (আসলে কী জমা আছে) আর value। s.Area() call করলে Go type slot পড়ে, সেই type-এর Area খুঁজে বের করে এবং জমানো value-র ওপর সেটা call করে। Interface তখনই nil যখন দুটো slot-ই খালি, আর এটাই একটা বিখ্যাত gotcha-র উৎস।

Run করে দেখুন

নিজে চেষ্টা করুন

  • “The (type, value) pair” উদাহরণে দেখুন Rect-এর জায়গায় Circle বসলে type slot কীভাবে বদলায়।
  • “The nil interface gotcha” উদাহরণে comparison-এর আগে interface box দুটো মিলিয়ে দেখুন। কোন slot-টা আলাদা?
  • “Type assertions” উদাহরণে comma-ok form আর যে form panic করে, এ দুটোর পার্থক্য খুঁজে বের করুন।

সাধারণ ভুল

  • Typed nil pointer-কে interface হিসেবে return করলে (var p *MyErr; return p) সেটা NON-nil interface হয়ে যায়। এর বদলে সরাসরি nil return করুন।
  • Interface বেশি বড় বানানো। ছোট interface (এক বা দুটো method, যেমন io.Reader) implement করা আর test করা দুটোই সহজ।
  • Implementation-এর পাশেই interface define করা। Go-তে সাধারণত interface থাকে সেই code-এর কাছে, যে code সেটা ব্যবহার করে।
  • শুধু x.(T) লিখলে x অন্য type ধরে থাকলে panic হয়। নিশ্চিত না হলে v, ok := x.(T) ব্যবহার করুন।
