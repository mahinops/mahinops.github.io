WaitGroup and Worker Pool

Worker pool একটা নির্দিষ্ট সংখ্যক worker দিয়ে একটা job-এর queue সামলায়। WaitGroup দিয়ে main অপেক্ষা করতে পারে যতক্ষণ না সব job শেষ হয়।

মূল ধারণা

একটা supermarket-এ আছে 3 টা checkout lane (worker) আর গ্রাহকদের একটা লাইন (job)। একটা lane খালি হলে সে পরের গ্রাহককে নেয়। 1000 জন গ্রাহকের জন্য 1000 টা lane খোলা হয় না; কয়েকটা lane-ই বারবার ব্যবহার হয়।

ম্যানেজারকে জানতে হয় সবাইকে সেবা দেওয়া হয়ে গেছে কিনা। sync.WaitGroup হলো একটা counter: প্রতিটা job-এর জন্য Add(1), একটা শেষ হলে Done(), আর Wait() block করে থাকে counter শূন্য না হওয়া পর্যন্ত।

Run করে দেখুন

নিজে চেষ্টা করুন

  • একই job দিয়ে 1 টা worker, তারপর 2, তারপর 4 টা দিন। মোট সময় কীভাবে বদলায়?
  • একটা job খুব লম্বা করুন (যেমন 9), বাকিগুলো ছোট। এটা কি বাকি worker-দের আটকে দেয়?
  • WaitGroup counter লক্ষ করুন: ঠিক কখন Wait() return করে?

সাধারণ ভুল

  • goroutine-এর ভেতরে wg.Add call করা: Add-এর আগেই Wait run হয়ে যেতে পারে। goroutine শুরু করার আগে Add করুন।
  • wg.Done() করতে ভুলে যাওয়া (defer wg.Done() ব্যবহার করুন): Wait চিরকাল block হয়ে থাকে।
  • jobs channel close না করা: যে worker গুলো এর ওপর range করছে তারা কখনো থামে না।
  • WaitGroup-কে value হিসেবে pass করা। এটা অবশ্যই pointer দিয়ে share করতে হবে।
