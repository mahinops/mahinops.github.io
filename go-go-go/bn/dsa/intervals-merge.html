Merge Intervals

যেসব time range একে অপরের সাথে overlap করে, সেগুলো মিলিয়ে সবচেয়ে কম সংখ্যক range বানান।

মূল ধারণা (calendar-এর meeting)

আপনার meeting আছে 1–3, 2–6 আর 8–10-এ। প্রথম দুটি overlap করে, তাই আপনার calendar-এ আসলে 1 থেকে 6 পর্যন্ত একটি busy block, আর 8–10। Interval merge করা যেকোনো list-এর জন্য ঠিক এটাই করে।

কৌশলটা হলো আগে start time ধরে sort করা। তাহলে overlap করা range গুলো পাশাপাশি এসে যায়, আর বাঁ থেকে ডানে একবার sweep করলেই যথেষ্ট:

  • merged নামে একটি list রাখুন। প্রথম interval দিয়ে শুরু করুন।
  • পরের প্রতিটি interval-এর start-কে শেষ merged interval-এর end-এর সাথে তুলনা করুন।
  • start ≤ সেই end হলে তারা overlap করে: শেষ interval-এর end-কে দুটি end-এর বড়টা পর্যন্ত বাড়িয়ে দিন।
  • না হলে মাঝে ফাঁক আছে: নতুন একটি merged interval শুরু করুন।

Run করে দেখুন

নিজে চেষ্টা করুন

  • Interval গুলো এলোমেলো order-এ লিখুন (default-টা এমনই)। sort করলে কি sweep ঠিকমতো কাজ করে?
  • 1-10, 2-3, 4-5 চেষ্টা করুন। নতুন interval যখন শেষটার পুরোপুরি ভেতরে থাকে, তখন end-এর জন্য কেন max ব্যবহার করতে হয়?
  • 1-3, 3-5 চেষ্টা করুন। এরা শুধু 3-এ ছুঁয়ে আছে। এই code কি এদের merge করে?
  • সব জায়গায় ফাঁক আছে এমন interval দিয়ে চেষ্টা করুন, যেমন 1-2, 4-5, 7-8।

সাধারণ ভুল

  • sort করতে ভুলে যাওয়া। Overlap করা interval গুলো পাশাপাশি নাও থাকতে পারে, আর sweep কোনো সতর্কতা ছাড়াই ভুল উত্তর দেয়।
  • end-কে max(last[1], cur[1])-এর বদলে cur[1] করা। আরেকটির ভেতরে থাকা interval ফলাফল ছোট করে দেবে।
  • ছুঁয়ে থাকা range-এ off-by-one। [1,3] আর [3,5] merge হবে কি না তা নির্ভর করে <= নাকি <-এর উপর। problem statement পড়ে নিন।
  • খালি input। খালি slice-এ intervals[0] panic করে, তাই আগে length দেখে নিন।
Complexity, সহজ ভাষায়: সবচেয়ে বেশি খরচ sort করায়, প্রায় n log n ধাপ (O(n log n))। এরপর sweep হলো একবারের pass (O(n))।
