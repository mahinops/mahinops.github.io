Backtracking

একটা choice নিয়ে দেখুন কোথায় যায়, তারপর সেটা undo করে পরের choice try করুন।

মূল ধারণা

চক পেনসিল হাতে একটা maze-এর ভেতর দিয়ে হাঁটার কথা ভাবুন: প্রতিটা মোড়ে একটা পথ বেছে নিয়ে এগিয়ে যান। বন্ধ রাস্তায় পৌঁছালে শেষ মোড় পর্যন্ত ফিরে আসুন (backtrack), চকের দাগ মুছে অন্য পথে যান। Backtracking সব সম্ভাবনা নিয়মমাফিক try করে, কিন্তু যে branch দিয়ে কাজ হবে না সেটা বুঝতে পারলেই ছেড়ে দেয়।

Pattern সবসময় একই: choose → explore (recursion) → un-choose। Subsets: প্রতিটা item-এর জন্য ঠিক করুন “নেব” নাকি “বাদ দেব”। N-Queens: প্রতি row-তে একটা queen বসান; কোনো ঘর attacked হলে সেটা বাদ দিন; কোনো row-তে একটাও safe ঘর না থাকলে আগের row-তে ফিরে গিয়ে আগের queen সরান।

Run করে দেখুন

নিজে চেষ্টা করুন

  • Subsets: চতুর্থ item যোগ করুন। এখন কয়টা leaf (subset) হয়? (প্রতিটা item-এ সংখ্যা দ্বিগুণ হয়।)
  • path লাইনটা দেখুন: “take” করলে বড় হয়, “backtrack” করলে ছোট হয়। ওই ছোট হওয়াটাই undo ধাপ।
  • N-Queens n = 4: লাল ঘরগুলো দেখুন। একটা ঘর কেন attacked, message-এ সেটা কী বলা আছে?
  • N-Queens: “প্রথম solution পেলেই থামুন” option-এ “না” দিন আর n = 4, 5 ও 6-এর জন্য কয়টা solution পাওয়া যায় গুনুন।

সাধারণ ভুল

  • Undo করতে ভুলে যাওয়া (“un-choose” ধাপ): তখন পরের branch-গুলো আগের choice-এর বাকি অংশ দেখতে পায়।
  • path copy না করে save করা: Go-তে append(res, path) এমন memory share করে যা পরে বদলে যায়। Copy করুন: append([]int{}, path...)।
  • Pruning না করা: শুধু শেষে safe কিনা check করলে দরকারের চেয়ে অনেক বেশি branch explore করতে হয়।

Complexity

Subsets: O(2n) সংখ্যক result, তাই সেগুলো বানাতে O(n·2n) time complexity। N-Queens: polynomial-এর চেয়ে খারাপ, কিন্তু pruning (attacked ঘর আগেই বাদ দেওয়া) করলে সব placement try করার তুলনায় search অনেক কমে যায়। Space complexity: O(n) recursion depth আর জমানো result।
