Dynamic Programming: Fill the Table

বড় সমস্যা সমাধানের আগে তার ছোট ছোট version সমাধান করুন এবং উত্তরগুলো একটি table-এ লিখে রাখুন।

মূল ধারণা (একই homework বারবার করবেন না)

ধরুন আপনাকে জিজ্ঞেস করা হলো, "একবারে 1 বা 2 ধাপ করে উঠলে 30টি সিঁড়ি কত উপায়ে ওঠা যায়?" শুরু থেকে আবার গুনতে না গিয়ে খেয়াল করুন: 30 নম্বর সিঁড়িতে দাঁড়াতে হলে আপনি এসেছেন 29 বা 28 নম্বর সিঁড়ি থেকে। তাই ways(30) = ways(29) + ways(28)। প্রতিটি উত্তর প্রথমবার বের করেই table-এ লিখে রাখলে, পরের প্রতিটি cell হলো আগে থেকে থাকা cell গুলোর একটা দ্রুত look-up মাত্র।

প্রতিটি DP problem-এর recipe একই:

  1. State: একটি cell-এর মানে কী? (যেমন "dp[i] = i সংখ্যক সিঁড়ি ওঠার উপায়")।
  2. Base case: যে cell গুলোর মান না ভেবেই জানা।
  3. Transition: আগের cell থেকে একটি cell বানানোর formula। ছবিতে হলুদ cell গুলোই হলো সেই cell, যেগুলো formula পড়ে।
  4. Order: এমনভাবে fill করুন যাতে প্রয়োজনীয় cell গুলো সবসময় আগে থেকেই তৈরি থাকে।
  5. Answer: সাধারণত শেষ cell।

Run করে দেখুন

নিজে চেষ্টা করুন

  • Stairs: n = 10 দিয়ে দেখুন। table-টা আসলে ছদ্মবেশে Fibonacci sequence।
  • LCS: AGGTAB আর GXTXAYB তুলনা করুন। দুটি অক্ষর মিলে গেলে cell কোন neighbor পড়ে?
  • LCS: একেবারে কোনো মিল নেই এমন দুটি string নিন। table কেমন দেখায়?
  • Knapsack: capacity বাড়ান এবং দেখুন item ঢুকে গেলে ("নিন") আর না ঢুকলে উপরের row-এর কোন cell গুলো ব্যবহার হয়।

সাধারণ ভুল

  • Table-এর size-এ off-by-one। n+1 by m+1 বানান, যাতে "খালি" row/column 0 থাকে, আর মনে রাখুন row i-এর অক্ষর হলো a[i-1]।
  • ভুল fill order। একটি cell শুধু সেই cell গুলো পড়বে যেগুলো আগেই fill করা হয়েছে।
  • Knapsack-এ "take" আর "skip" গুলিয়ে ফেলা। Item i নিলে উপরের row-এর c - weight cell পড়তে হয়, একই row নয় (একই row পড়লে একটি item দুইবার ব্যবহার করা যেত)।
  • Overlapping problem-এ সাধারণ recursion ব্যবহার করা। table বা memo ছাড়া একই sub-problem বারবার সমাধান হয়, যা exponential সময় নিতে পারে।
Complexity, সহজ ভাষায়: কাজ cell-এর সংখ্যার সমান, প্রতিটি cell fill হয় constant সময়ে। Stairs: O(n)। LCS: O(m × n)। Knapsack: O(items × capacity)। table ছাড়া একই recursion exponential হারে ধীর হতে পারে।
