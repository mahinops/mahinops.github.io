Linked List

Box-এর একটা chain, যেখানে প্রতিটা box শুধু পরেরটাকে চেনে।

মূল ধারণা

Linked list অনেকটা treasure hunt-এর মতো: প্রতিটা clue (node)-এ একটা value থাকে আর বলা থাকে পরের clue কোথায়। সরাসরি 5 নম্বর clue-তে যাওয়া যায় না; শুরু থেকে chain ধরে এগোতে হয়। শেষ clue-টা nil (কিছু নেই) দেখায়।

Reverse করা মানে প্রতিটা arrow উল্টে দেওয়া। এজন্য তিনটা helper লাগে: prev (যে অংশ reverse হয়ে গেছে), curr (যে node এখন ঠিক করা হচ্ছে) আর next (আগে থেকে save করা, যাতে arrow উল্টানোর পর বাকি chain হারিয়ে না যায়)।

Cycle detection: একটা ট্র্যাকে দুজন দৌড়বিদ, একজন অন্যজনের দ্বিগুণ জোরে। ট্র্যাক গোলাকার (loop) হলে দ্রুতজন একসময় ধীরজনকে এক চক্কর ছাড়িয়ে যায় আর তারা মিলে যায়। ট্র্যাক সোজা হলে দ্রুতজন শুধু শেষ প্রান্ত দিয়ে বেরিয়ে যায়।

Run করে দেখুন

নিজে চেষ্টা করুন

  • Reverse: ধীরে ধীরে step করে এই ক্রমটা দেখুন: next save করা → arrow উল্টানো → prev সরানো → curr সরানো। next save করার আগে arrow উল্টালে কী ভুল হয়?
  • এক value-র list reverse করুন, তারপর দুই value-র। Code-এ কি আলাদা special case লাগে?
  • Cycle: back-index -1 দিন (cycle নেই) আর দেখুন fast কীভাবে শেষ প্রান্ত দিয়ে বেরিয়ে যায়।
  • Cycle: back-index 0 দিন, তারপর শেষ index দিন (একটা node নিজেকেই দেখাচ্ছে)। তবুও কি cycle ধরা পড়ে?

সাধারণ ভুল

  • curr.Next save করার আগে উল্টে দেওয়া: বাকি list হারিয়ে যায়।
  • Reverse করার পর head return করা: আগের head এখন tail। prev return করুন।
  • fast.Next.Next-এর আগে fast.Next != nil check না করা: এতে nil pointer dereference panic হয়।
  • Array-র মতো linked list-এ index দিয়ে যাওয়া: k নম্বর item-এ পৌঁছাতে k ধাপ লাগে।

Complexity

Reverse: O(n) time complexity, O(1) space complexity – একবার pass, তিনটা pointer। Cycle detection: O(n) time complexity, O(1) space complexity – hash-set দিয়ে করলে লাগে O(n) space complexity, সেটার সাথে তুলনা করুন।
